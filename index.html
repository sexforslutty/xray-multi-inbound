# `xray-multi-inbound`

### Xray Core × Remnawave **Multi-Inbound конфигурация с VLESS + REALITY** `TCP` · `XHTTP` · `gRPC` · `REALITY` · `Self-Steal` · `Routing`

--- ## ✦ О проекте `xray-multi-inbound` — готовая конфигурация **Xray Core**, предназначенная для использования совместно с **Remnawave**. Проект объединяет несколько способов подключения в одном серверном конфиге: * `VLESS + REALITY` * `TCP` * `XHTTP` * `gRPC` * `Self-Steal` * серверную маршрутизацию * клиентский routing * локальные `SOCKS5` / `HTTP` подключения Конфигурация построена таким образом, чтобы разные транспорты могли работать параллельно на одном сервере. > **Автор:** `sexforslutty` --- # ✦ Архитектура ```text ┌───────────────────────┐ │ REMNAWAVE │ │ User Management │ └───────────┬───────────┘ │ ▼ ┌───────────────────────┐ │ XRAY CORE │ │ │ │ VLESS + REALITY │ └───────────┬───────────┘ │ ┌──────────────────────┼──────────────────────┐ │ │ │ ▼ ▼ ▼ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ TCP │ │ XHTTP │ │ gRPC │ │ :56789 │ │ :56790 │ │ :56791 │ └──────┬──────┘ └──────┬──────┘ └──────┬──────┘ │ │ │ └─────────────────────┼─────────────────────┘ │ ▼ ┌─────────────────┐ │ REALITY │ │ Self-Steal │ └────────┬────────┘ │ ▼ Интернет ``` --- # ✦ Возможности | Возможность | Поддержка | | ----------------------- | :-------: | | VLESS | ✓ | | REALITY | ✓ | | TCP | ✓ | | XHTTP | ✓ | | gRPC | ✓ | | Self-Steal | ✓ | | Remnawave | ✓ | | IPv4 DNS strategy | ✓ | | HTTP/TLS sniffing | ✓ | | Private IP blocking | ✓ | | Private domain blocking | ✓ | | BitTorrent blocking | ✓ | | Server-side routing | ✓ | | Client-side routing | ✓ | | SOCKS5 inbound | ✓ | | HTTP inbound | ✓ | | Traffic statistics | ✓ | --- # ✦ Inbounds Конфигурация содержит три основных публичных inbound'а. | Tag | Protocol | Transport | Security | Port | | ----------------- | -------- | --------- | -------- | ------: | | `TCP-SELFSTEAL` | VLESS | TCP | REALITY | `56789` | | `XHTTP-SELFSTEAL` | VLESS | XHTTP | REALITY | `56790` | | `GRPC-SELFSTEAL` | VLESS | gRPC | REALITY | `56791` | Все три inbound'а используют: ```text VLESS ↓ REALITY ↓ Self-Steal ``` Входящие подключения слушаются на: ```text 0.0.0.0 ``` --- # ✦ 1. TCP + REALITY **Tag** ```text TCP-SELFSTEAL ``` **Port** ```text 56789 ``` **Transport** ```text TCP ``` **Security** ```text REALITY ``` TCP-вариант является самым простым и универсальным способом подключения. Пример структуры: ```json { "tag": "TCP-SELFSTEAL", "port": 56789, "protocol": "vless", "streamSettings": { "network": "tcp", "security": "reality" } } ``` --- # ✦ 2. XHTTP + REALITY **Tag** ```text XHTTP-SELFSTEAL ``` **Port** ```text 56790 ``` **Transport** ```text XHTTP ``` **Security** ```text REALITY ``` XHTTP использует отдельные настройки транспорта: ```json "xhttpSettings": { "host": "ваш selfsteal домен", "mode": "auto", "path": "/" } ``` XHTTP inbound: ```text XHTTP ↓ REALITY ↓ Self-Steal ``` --- # ✦ 3. gRPC + REALITY **Tag** ```text GRPC-SELFSTEAL ``` **Port** ```text 56791 ``` **Transport** ```text gRPC ``` **Security** ```text REALITY ``` Используемый `serviceName`: ```text grpc-reality ``` Конфигурация транспорта: ```json "grpcSettings": { "multiMode": false, "serviceName": "grpc-reality" } ``` --- # ✦ Self-Steal Self-Steal используется как механизм REALITY-конфигурации. Основные параметры: ```json "realitySettings": { "target": "127.0.0.1:8081", "spiderX": "/", "shortIds": [ "ваш short id" ], "privateKey": "ваш private key", "fingerprint": "firefox", "serverNames": [ "ваш selfsteal домен" ] } ``` Перед запуском необходимо заменить: ```text ваш short id ваш private key ваш selfsteal домен ``` на собственные значения. > **Важно:** не публикуйте `privateKey` в GitHub или других публичных репозиториях. --- # ✦ DNS Конфигурация использует стратегию: ```text UseIPv4 ``` DNS-серверы: ```text 1.1.1.1 9.9.9.9 localhost ``` Конфигурация: ```json "dns": { "servers": [ "1.1.1.1", "9.9.9.9", "localhost" ], "queryStrategy": "UseIPv4" } ``` --- # ✦ Routing Маршрутизация разделяет трафик на несколько категорий. ```text TRAFFIC │ ┌─────────────┼─────────────┐ │ │ │ ▼ ▼ ▼ PRIVATE TORRENT NORMAL │ │ │ ▼ ▼ ▼ BLOCK BLOCK DIRECT ``` ### BLOCK Блокируются: ```text geoip:private geosite:private bittorrent ``` То есть конфигурация не позволяет использовать Xray для доступа к приватным адресам и BitTorrent-трафику. --- # ✦ Outbounds В конфигурации присутствуют два основных outbound'а: ### DIRECT ```json { "tag": "DIRECT", "protocol": "freedom" } ``` Используется для прямого выхода в интернет. ### BLOCK ```json { "tag": "BLOCK", "protocol": "blackhole" } ``` Используется для блокировки трафика. --- # ✦ Client Routing Клиентская маршрутизация использует модель: ```text PROXY DIRECT BLOCK ``` Основная идея: ```text Россия / локальный трафик ↓ DIRECT Выбранные домены ↓ PROXY Запрещённый трафик ↓ BLOCK ``` Это позволяет не отправлять весь трафик через прокси и использовать сервер только там, где это необходимо. --- # ✦ Remnawave Конфигурация рассчитана на использование вместе с Remnawave. Общая схема: ```text Remnawave │ ├── Users ├── Nodes ├── Subscription │ ▼ Xray Core │ ├── VLESS TCP ├── VLESS XHTTP └── VLESS gRPC ``` Remnawave используется для управления пользователями и параметрами подключений, а Xray Core непосредственно обрабатывает соединения. --- # ✦ Быстрый старт ## 1. Скачать конфигурацию ```bash git clone https://github.com/sexforslutty/xray-multi-inbound.git cd xray-multi-inbound ``` --- ## 2. Подготовить конфигурацию Откройте: ```text multi cfg tcp - xhttp - grpc.json ``` Необходимо изменить значения: ```text ваш short id ваш private key ваш selfsteal домен ``` --- ## 3. Настроить REALITY Сгенерируйте собственные параметры REALITY и укажите их в конфигурации. В частности: ```text Private Key Short ID Server Name Target ``` Не используйте чужие приватные ключи. --- ## 4. Открыть порты На сервере должны быть доступны: ```text 56789/tcp 56790/tcp 56791/tcp ``` Пример для UFW: ```bash sudo ufw allow 56789/tcp sudo ufw allow 56790/tcp sudo ufw allow 56791/tcp ``` Если используется другой firewall или панель управления сервером — откройте соответствующие порты там. --- # ✦ Проверка конфигурации Перед запуском обязательно проверьте JSON: ```bash xray run -test -config "multi cfg tcp - xhttp - grpc.json" ``` Если конфигурация корректна, Xray не должен вернуть ошибки парсинга. После проверки можно запускать: ```bash xray run -config "multi cfg tcp - xhttp - grpc.json" ``` --- # ✦ Структура репозитория ```text xray-multi-inbound/ │ ├── multi cfg tcp - xhttp - grpc.json │ ├── routing.json │ └── readme.md ``` ### `multi cfg tcp - xhttp - grpc.json` Основная конфигурация Xray Core. Содержит: * DNS * TCP inbound * XHTTP inbound * gRPC inbound * REALITY * Self-Steal * outbounds * routing * policy ### `routing.json` Файл для клиентской маршрутизации. Используется для разделения трафика между: ```text PROXY DIRECT BLOCK ``` ### `readme.md` Основная документация проекта. --- # ✦ Рекомендованный порядок настройки ```text 01 ── Подготовить VPS │ 02 ── Установить Xray Core │ 03 ── Настроить домен │ 04 ── Настроить Self-Steal │ 05 ── Сгенерировать REALITY параметры │ 06 ── Заполнить конфигурацию │ 07 ── Открыть порты │ 08 ── Проверить конфиг │ 09 ── Подключить Xray к Remnawave │ 10 ── Настроить subscription template │ 11 ── Проверить клиентское подключение ``` --- # ✦ Troubleshooting ## Xray не запускается Проверьте конфигурацию: ```bash xray run -test -config "multi cfg tcp - xhttp - grpc.json" ``` Также проверьте JSON на наличие незаменённых значений: ```text ваш short id ваш private key ваш selfsteal домен ``` --- ## Порт недоступен Проверьте, слушает ли Xray нужный порт: ```bash ss -lntp | grep -E '56789|56790|56791' ``` Проверьте firewall: ```bash sudo ufw status ``` --- ## REALITY не подключается Проверьте соответствие: ```text Private Key Short ID Server Name Target Fingerprint ``` Особое внимание уделите `serverNames` и параметрам клиента. --- ## XHTTP не работает Проверьте: ```text port → 56790 network → xhttp security → reality host → ваш домен path → / mode → auto ``` --- ## gRPC не работает Проверьте: ```text port → 56791 network → grpc security → reality serviceName → grpc-reality ``` --- # ✦ Безопасность Никогда не публикуйте в репозитории: ```text Private Key UUID API tokens Passwords Subscription secrets SSH keys ``` Если секрет уже попал в публичный Git-репозиторий — считайте его скомпрометированным и замените. --- # ✦ Документация Полезные официальные материалы: * [Xray Core](https://github.com/XTLS/Xray-core) * [Xray Documentation](https://xtls.github.io/) * [Xray — Inbound Configuration](https://xtls.github.io/config/inbound.html) * [Remnawave](https://github.com/remnawave) --- # ✦ Repository
